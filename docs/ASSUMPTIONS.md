# Assumptions and verification boundaries

## Dual institution and prospective evaluation update

VTU and BMSIT now have separate collections and prediction histories. Their actual
paper patterns remain **UNVERIFIED**. The developer chooses the institution and
assessment type; neither is inferred from a PDF. Source authenticity, completeness
and topic labels require human review. PDF header validation is not content review.

The prospective score uses all listed question marks and any matching topic. It
does not assume official maximum marks, optional-choice behavior or a student's
grade. Those interpretations remain **UNVERIFIED**. Same-year papers are excluded
from training. Real-world forecasting effectiveness and statistical significance
remain **NOT VERIFIED**; synthetic software tests do not establish either.

## BMSIT scope added after M0

The user states that BMSIT prepares its own internal and semester-end papers.
This is the application's intended scope, not independently verified institutional
policy. BMSIT marks, modules, numbering, scheme rules, departments, semesters, and
assessment schedules remain **UNVERIFIED**. No official affiliation is implied.
Internal assessments and semester-end exams now have separate dataset histories.
The toy M0 fixtures remain synthetic and are not relabeled as real BMSIT papers.

The original read-only UI boundary was superseded by the explicit login/profile
request. Current collection counts and prospective scores are pipeline-derived.
Without an earlier saved prediction and reviewed target data, scores remain
unavailable. Legacy UI observations below refer to the unloaded original prototype.

| Area | Status | Current treatment |
| --- | --- | --- |
| VTU scheme names and scheme years | UNVERIFIED | Only explicitly synthetic identifiers are configured. No real scheme is claimed. |
| VTU paper modules, numbering, sub-parts, marks, choices, and maximum marks | UNVERIFIED | The structure file is a toy set of question slots. All values are inputs, not inferred facts. |
| Subject and topic catalog | UNVERIFIED for real exams | Synthetic subjects and synthetic topics are generated from config. |
| Meaning of a scheme year | UNVERIFIED for VTU | `Scheme.year` records a declared scheme year; `Paper.year` independently records the sitting year. |
| Question position | UNVERIFIED for real papers | A number plus optional sub-part is unique within a paper. Numbers remain strings so alternate conventions fit. |
| Question marks | UNVERIFIED for real papers | The current contract accepts only finite positive marks. Fractional marks are supported. Zero-mark headings are not questions in this contract. |
| Module assignment | UNVERIFIED for real papers | Each question/topic has one module; labels must stay in that module. Cross-module questions would need a deliberate contract revision. |
| Multiple sittings | UNVERIFIED for VTU | A sitting is an opaque configured string; different sittings can share a calendar year. |
| Syllabus changes | UNVERIFIED | Topics are scoped to a subject and scheme. No drift/alias workflow is implemented. |
| Optional questions | UNVERIFIED | All toy slots are present. Choice groups, optional answers, and offered-versus-attempted marks are not modeled. |
| Repeat patterns | SYNTHETIC ONLY | A randomly selected preferred pool remains stable across years within a generated subject/module. This is an experimental construction. |
| Pure noise | SYNTHETIC ONLY | Topic selection is uniform without replacement per paper/module. Fixed module slots remain a constraint; repeated topics by chance are expected. |
| Forecast quality and statistical significance | NOT EVALUATED | M0 validates data construction only. M2 will implement forecasting, leakage checks, and evaluation. |
| UI numbers | LEGACY SYNTHETIC PLACEHOLDERS | The read-only prototype has no connection to the Python pipeline. Its manually supplied values are not experimental evidence. |

Configuration numbers are declared inputs. Fixture counts and hashes are computed
by the generator. No hand-written performance scores or empirical result tables
are supplied by M0.

Reproducibility means identical configuration, generator version, and Python random
implementation produce identical dataset bytes. Cross-Python-version byte identity
has not been established. Preserve generated bytes and hashes for comparisons.

Synthetic generation cannot establish performance on real exams. Before accepting
real data, verify its scheme, paper rules, topic catalog, and handling of optional
questions. M0 does not require or ingest any real data.
